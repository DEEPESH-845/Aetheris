## 1. Executive Summary

### Project Purpose
Aetheris is an **AI-driven autonomous cyber deception and active defense platform**. It visualizes simulated threat telemetry, AI reasoning via LangGraph, sandbox twin orchestration, eBPF kernel-level monitoring, and autonomous defensive operations through a cyberpunk-themed command center dashboard.

### Current Maturity Level: **28/100 — Early Prototype**
The project is a functional **single-user demo/proof-of-concept** with impressive visual polish and sophisticated simulation logic. It is NOT production-ready for commercial SaaS deployment.

## 2. Complete Project Understanding

### What the Project Actually Does

Aetheris runs a **simulated cyber defense scenario** through a 6-phase pipeline:

1. **Detection** (Phase 1-2): Zeek, Suricata, and eBPF telemetry generators produce realistic security events
2. **AI Reasoning** (Phase 4): LangGraph state machine (ingest → enrich → analyze → mitigate) processes threats with MITRE ATT&CK correlation and attacker attribution
3. **Sandbox Orchestration** (Phase 5): Spawns "sandbox twins" (decoy systems) via simulated Terraform/Ansible, creating air-gapped environments for attacker containment
4. **Defensive Operations** (Phase 6): Executes autonomous countermeasures (ISOLATE_NODE, BLOCK_ASN, TERMINATE_PROCESS, ENFORCE_ZERO_TRUST)

### User Journey

1. User visits **/** (landing page) → clicks Sign In → Clerk authentication
2. User enters **/dashboard** (Command Center) → sees live threat score, network topology, telemetry feed, AI reasoning stream
3. User navigates to **/dashboard/sandbox** → triggers attack vectors (APT Cobalt Strike, Ransomware, etc.) → watches sandbox twin spawn and attacker session play out
4. User navigates to **/dashboard/ai-core** → views LangGraph state machine visualization, MITRE ATT&CK correlation matrix, attacker profile
5. User visits **/dashboard/settings** → adjusts AI aggressiveness, DEFCON level, telemetry sensors

### System Architecture

```
Next.js 16 Frontend (Vercel) ←——WebSocket——→ Python FastAPI Backend (Railway)
         │                                              │
    Clerk Auth (JWT)                            LangGraph AI Core
    Zustand Store (in-memory)                   asyncio.Queue (in-memory)
    Framer Motion + Recharts                    Simulated telemetry
    No database                                No database
```

**Critical architectural fact**: There is NO database anywhere in this project. All state is ephemeral — the Zustand store resets on page refresh, and the backend uses `asyncio.Queue` for transient message passing.

### Data Flow

```
[Local Generator] or [WebSocket Backend]
        ↓
  useSimulationStore (Zustand)
        ↓
  React Components (Re-render)
        ↓
  Framer Motion Animations
```

The simulation engine (`src/simulation/engine.ts:271-556`) has dual data sources:
- **Primary**: WebSocket connection to FastAPI backend with Clerk JWT auth
- **Fallback**: Local `setInterval` generator at 800ms ticks producing Zeek/Suricata/eBPF events

When WebSocket connects, local generator suspends. On disconnect, local generator resumes. This is the only resilience mechanism in the system.

### Authentication

**Frontend**: Clerk (`@clerk/nextjs` v7.4.2) with dark theme customization
- Root layout wraps in `<ClerkProvider>` (`src/app/layout.tsx:28-74`)
- Middleware at `src/proxy.ts` (MISNAMED — should be `middleware.ts`) protects `/dashboard(.*)` and `/sandbox(.*)`

**Backend**: JWT verification via `PyJWKClient` (`backend/main.py:32-57`)
- Decodes Clerk publishable key to extract JWKS domain
- Verifies tokens with RS256 algorithm
- **CRITICAL BUG**: Returns `True` (bypass) when JWKS client is `None` (`backend/main.py:49-50`)

## 7. X-Factor Premium Differentiators

### 7.1 AI Deception Twinning

- **Problem Solved**: Static honeypots are easily fingerprinted by sophisticated attackers
- **Why Competitors Lack It**: Attivo, Illusive Networks use static decoys. No competitor dynamically spawns digital twins that mirror production systems in real-time
- **Technical Feasibility**: The simulation engine (`engine.ts:231-250`) already demonstrates twin spawning logic. Connect to real Proxmox/KVM API.
- **Business Value**: THIS IS THE CORE DIFFERENTIATOR. Autonomous, adaptive deception is the product moat.
- **Monetization**: Pro+ tier ($99+/mo)
- **Development Effort**: 4-6 weeks (connect to real infrastructure)
- **Defensibility**: HIGH — requires deep integration of AI + infrastructure + security domain knowledge

### 7.2 Real-Time MITRE ATT&CK Correlation

- **Problem Solved**: Post-mortem analysis is too late — defenders need live kill chain mapping
- **Why Competitors Lack It**: Most tools map TTPs after the fact. Aetheris maps them in real-time during active attacks
- **Technical Feasibility**: The `MITRE_TTPS` data pool (`engine.ts:45-57`) and `AttackerProfile` type already exist. Connect to real threat intel feeds.
- **Business Value**: HIGH — compliance teams love MITRE mapping
- **Monetization**: Starter+ ($29+/mo)
- **Development Effort**: 2-3 weeks
- **Defensibility**: MEDIUM — MITRE is public data, but real-time correlation is hard

### 7.3 eBPF-Native Telemetry

- **Problem Solved**: Network taps and host agents add overhead and can be evaded
- **Why Competitors Lack It**: Cilium eBPF integration gives kernel-level visibility without agents — most competitors rely on user-space monitoring
- **Technical Feasibility**: The eBPF event generator (`engine.ts:170-190`) and Cilium sensor panel (`orchestration/page.tsx`) already exist. Connect to real Cilium API.
- **Business Value**: HIGH — zero-overhead monitoring is a strong selling point
- **Monetization**: Pro+ ($99+/mo)
- **Development Effort**: 3-4 weeks
- **Defensibility**: HIGH — eBPF expertise is rare

### 7.4 Deception-as-Code

- **Problem Solved**: Manual honeypot configuration doesn't scale
- **Why Competitors Lack It**: No competitor offers version-controlled, API-driven deception infrastructure
- **Technical Feasibility**: The orchestration page (`orchestration/page.tsx`) shows Terraform/Ansible workflow. Add YAML config parser and API.
- **Business Value**: HIGH — DevSecOps teams want infrastructure-as-code for everything
- **Monetization**: Business+ ($299+/mo)
- **Development Effort**: 3-4 weeks
- **Defensibility**: VERY HIGH — unique capability, hard to replicate

### 7.5 AI Reasoning Transparency

- **Problem Solved**: "Black box" AI erodes trust in security tools
- **Why Competitors Lack It**: Most AI security tools show only the output, not the reasoning process
- **Technical Feasibility**: The LangGraph visualization (`ai-core/page.tsx`) already shows the full state machine. Make it interactive and explorable.
- **Business Value**: VERY HIGH — builds trust with security engineers who are skeptical of AI
- **Monetization**: All tiers (differentiator)
- **Development Effort**: 1-2 weeks (polish existing)
- **Defensibility**: MEDIUM — unique UX, but concept is replicable

### 7.6 Autonomous Playbook Generation

- **Problem Solved**: Writing defensive playbooks manually is slow and error-prone
- **Why Competitors Lack It**: SOAR tools have pre-built playbooks, but none generate custom playbooks from AI analysis of the specific attack
- **Technical Feasibility**: The defensive operations (`defensive-ops/page.tsx`) already simulate playbook execution. Add LLM-based playbook generation.
- **Business Value**: VERY HIGH — autonomous defense is the endgame
- **Monetization**: Business+ ($299+/mo)
- **Development Effort**: 4-6 weeks
- **Defensibility**: HIGH — requires AI + security domain expertise

## 8. UX Review

- **Issues**: No breadcrumbs, no search, no keyboard shortcuts, no mobile hamburger menu
- **Recommendation**: Add breadcrumbs, Cmd+K search palette, mobile responsive sidebar

### Information Architecture
- **Current**: Logical grouping (Command Center → Monitor → AI → Topology → Orchestration → Defense → Sandbox → Settings)
- **Issues**: No admin section, no analytics, no billing, no profile settings
- **Recommendation**: Add admin section (visible to ADMIN/OWNER roles only)

### Accessibility (WCAG)
- **Current**: No ARIA labels, no skip links, no focus management, no screen reader support
- **Issues**: All text is small (10-12px), neon colors on dark backgrounds may fail contrast ratios
- **Recommendation**: Add ARIA labels, focus indicators, skip links, test with screen readers

### Responsiveness
- **Current**: Desktop-only layout (fixed sidebar, fixed navbar)
- **Issues**: Sidebar is 280px fixed width — breaks on tablets. No mobile layout.
- **Recommendation**: Mobile-first responsive design, collapsible sidebar to overlay on mobile

### Error States
- **Current**: Zero error boundaries. No empty states. No loading skeletons.
- **Issues**: Any error crashes the entire dashboard. No graceful degradation.
- **Recommendation**: Add React error boundaries, loading skeletons, empty state illustrations

### Onboarding
- **Current**: None. User lands on empty Command Center.
- **Issues**: No guided tour, no tooltips, no getting started checklist
- **Recommendation**: Interactive onboarding tour, contextual tooltips, getting started checklist

### Micro-Interactions
- **Current**: Excellent. Framer Motion animations are polished — staggered reveals, layout animations, scroll triggers.
- **Assessment**: This is a STRONG POINT. The cyberpunk aesthetic is distinctive and well-executed.

### Visual Hierarchy
- **Current**: Good. Clear distinction between primary actions (neon-cyan), secondary info (text-secondary), and background.
- **Issues**: Some panels have competing visual weight. Threat score and AI reasoning compete for attention.
- **Recommendation**: Establish clearer information hierarchy with size/color/spacing rules

### Redesign Recommendations
1. Add mobile responsive layout
2. Add Cmd+K search palette
3. Add loading skeletons for all data-dependent components
4. Add empty state illustrations for when no threats/simulations exist
5. Add breadcrumbs for deep navigation

## 10. Stripe Integration Design

### Products & Pricing

| Plan | Monthly | Yearly (2 mo free) | Target Customer |
|------|---------|-------------------|-----------------|
| Free | $0 | $0 | Individual researchers, evaluation |
| Starter | $29/mo | $290/yr | Small SOC teams (1-5 people) |
| Pro | $99/mo | $990/yr | Mid-size security teams (5-15) |
| Business | $299/mo | $2,990/yr | Enterprise SOCs (15-50) |
| Enterprise | Custom | Custom | Large enterprises, MSSPs |

### Subscription Lifecycle

```
Free → Starter: Instant upgrade via Checkout
Starter → Pro: Prorated upgrade, immediate feature access
Pro → Starter: Prorated downgrade, takes effect at period end
Any → Enterprise: Manual sales process, custom invoicing
```

### Failed Payment Recovery

1. **First failure**: Stripe Smart Retries (automatic)
2. **Second failure** (day 3): Email notification + in-app banner
3. **Third failure** (day 7): 7-day grace period, features reduced to Starter
4. **Fourth failure** (day 14): Downgrade to Free, data preserved for 30 days
5. **After 30 days**: Data archived, account flagged

### Trial Management

- 14-day free trial on all paid plans
- Warning emails at 7, 3, 1 day(s) remaining
- Auto-downgrade to Free after trial if no payment method
- Can convert trial to paid without losing data

### Webhook Events to Handle

- `checkout.session.completed` — Activate subscription
- `customer.subscription.updated` — Plan change
- `customer.subscription.deleted` — Downgrade to Free
- `invoice.payment_failed` — Recovery flow
- `invoice.paid` — Extend subscription
- `customer.subscription.trial_will_end` — Trial warning

## 12. Cybersecurity Assessment

### OWASP Top 10 Analysis

| Category | Risk Level | Evidence | Mitigation |
|----------|-----------|----------|------------|
| **A01: Broken Access Control** | CRITICAL | Middleware not active (`proxy.ts`), auth bypass (`main.py:49-50`) | Rename middleware, fix bypass, add RBAC |
| **A02: Cryptographic Failures** | HIGH | JWT verification uses RS256 (good), but no encryption at rest (no DB) | Add database encryption, enforce TLS |
| **A03: Injection** | MEDIUM | WebSocket input validation is minimal (`main.py:296-299` only sanitizes envId) | Add comprehensive input validation with Zod |
| **A04: Insecure Design** | HIGH | No multi-tenancy, no data isolation, single global state store | Implement row-level tenant isolation |
| **A05: Security Misconfiguration** | CRITICAL | No security headers, permissive CORS, empty `next.config.ts` | Add headers, restrict CORS, configure properly |
| **A06: Vulnerable Components** | HIGH | Unpinned Python deps (`requirements.txt`), no npm audit | Pin versions, run security audits |
| **A07: Auth Failures** | CRITICAL | Auth bypass, no brute-force protection, no MFA | Fix bypass, add rate limiting, require MFA for admin |
| **A08: Data Integrity Failures** | HIGH | No CSRF protection, no input sanitization beyond envId | Add CSRF tokens, validate all inputs |
| **A09: Logging Failures** | HIGH | Basic Python logging only, no structured logging, no audit trail | Add structured logging, audit log model |
| **A10: SSRF** | LOW | No URL fetching in application code | N/A currently, monitor if URL fetching added |

### Specific Vulnerabilities

**VULN-001: Authentication Bypass (CVSS 9.8)**
- **Evidence**: `backend/main.py:49-50`
- **Risk**: Complete auth bypass when `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` is unset
- **Likelihood**: HIGH (happens in dev/staging if env vars not configured)
- **Impact**: CRITICAL — unauthenticated WebSocket access to all telemetry data
- **Mitigation**: Return `False` when JWKS client is None. Add startup validation.

**VULN-002: Route Protection Bypass (CVSS 8.1)**
- **Evidence**: `src/proxy.ts` — Next.js requires `middleware.ts`
- **Risk**: All dashboard routes publicly accessible
- **Likelihood**: CERTAIN (file naming is wrong)
- **Impact**: HIGH — unauthenticated users can access all dashboard pages
- **Mitigation**: Rename file to `middleware.ts`

**VULN-003: Permissive CORS (CVSS 5.3)**
- **Evidence**: `backend/main.py:26-29`
- **Risk**: Cross-origin requests from any domain allowed
- **Likelihood**: MEDIUM
- **Impact**: MEDIUM — could enable CSRF-like attacks
- **Mitigation**: Restrict to specific origins, methods, and headers

**VULN-004: No Rate Limiting on Auth (CVSS 5.3)**
- **Evidence**: `backend/main.py:282-289` — only PROVISION_SANDBOX is rate-limited
- **Risk**: Brute-force JWT token attempts, DoS via WebSocket connections
- **Likelihood**: MEDIUM
- **Impact**: MEDIUM — potential service degradation
- **Mitigation**: Add global rate limiting for all message types

**VULN-005: No Security Headers (CVSS 4.3)**
- **Evidence**: `next.config.ts` is empty
- **Risk**: Clickjacking, MIME sniffing, XSS
- **Likelihood**: HIGH (trivially exploitable)
- **Impact**: MEDIUM — client-side attacks possible
- **Mitigation**: Add CSP, X-Frame-Options, HSTS, etc.

│              └── Telemetry Generation                         │
│                    ↓                                          │

### High Availability Design

1. **Frontend**: Vercel handles HA automatically (multi-region, auto-scaling)

4. **Redis**: Upstash with automatic failover
5. **WebSocket**: Redis PubSub enables horizontal scaling of WebSocket connections
